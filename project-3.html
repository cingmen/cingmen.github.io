01.

Overview

Background. A honeypot network I run captured 74 unique MIPS/ARM binaries over six months — all truck-driver copies of a Mirai descendant with a rebranded C2 scheme. AV verdicts were mostly generic, and no public report had mapped the newer variant's full lifecycle.

Target. Produce a defensible attribution baseline: triage the corpus, reverse the C2 protocol, map config encryption, and hand SOC teams production-ready YARA rules and IOC feeds — with every claim traceable to a reproducible dynamic trace.

All detonation ran inside a patched, network-isolated QEMU lab emulating four common IoT device profiles; no live third-party infrastructure was contacted during controlled runs.

02.

The Challenge

The corpus resisted off-the-shelf analysis in three ways:

  • Config obfuscation. Each binary carries an XOR-encoded config blob whose key is derived at runtime from the build timestamp — static string extraction produced garbage.
  • Packed with UPX-plus — a modified UPX header that crashes the stock unpacker, so manual unpack via debugger was required per sample.
  • Anti-emulation checks. The bot sleeps for a randomized interval and probes its own /proc for QEMU markers before activating, lulling naive dynamic runs into false quietness.
03.

The Execution

Methodology

Each sample moved through the same pipeline: acquire → fingerprint → unpack → detonate in profiled emulation → protocol extract → config decrypt → correlate across the corpus → IOC/YARA publish. Findings were cross-checked against internal differential hashing so the final product was one taxonomy, not 74 anecdotes.

Ghidra QEMU + custom profiles Wireshark Python 3 YARA Volatility-style tracing

Step 1 — Triage & clustering

Imphash, section entropy and bfelf-tag clustering reduced 74 binaries to 6 distinct builds of one family lineage:

terminal — corpus triage 
$ python3 triage.py --dir samples/ --cluster imphash,entropy
# 74 samples / avg entropy 7.82 (packed)
[+] 6 clusters: A(32) B(14) C(11) D(9) E(5) F(3)
[+] shared loader skeleton across all clusters (95% bb-match)
# conclusion: one lineage, six build waves

Step 2 — Unpacking & config extraction

Manual UPX-plus unpacking under Ghidra surfaced the runtime key derivation. The encrypted config decrypts to a structured blob — C2 table, kill-switch domain, and per-build flood settings:

idapython — config decrypt 
# key = rot32(build_ts) XOR 0x5A per config.py reconstruction
[+] 42 unique C2 endpoints recovered across corpus
[+] kill-switch domain: watchbog[.]support (lame infra)
[+] flood table: UDP-amp 4 / TCP-SYN 3 / HTTP-choke 2

Step 3 — C2 protocol reconstruction

Decoded traffic from detonated samples showed a plaintext TLV-over-TCP protocol with a checksum byte. Worst part: the !SCAN directive leaks third targets — usable for takedown coordination:

poc.py — tlv decode 
#!/usr/bin/env python3
"""TLV decoder rebuilt from dynamic traces - research use."""
import struct

def parse(buf):
    t, l = struct.unpack(">BH", buf[:3])
    val = buf[3:3+l]
    # t=0x01 keep-alive | 0x02 scan-directive | 0x03 flood
    return (t, val)

# sample decoded directive:
# (0x02, b'188.34.0.0/16 22 60')  -> scan netmask, port, duration

Step 4 — IOC & YARA production

The study shipped 42 IOCs, 9 YARA rules validated against a 400k-sample public corpus with zero false positives, and a Sigma rule for the unique !SCAN directive fingerprint on the wire.

04.

The Impact & Mitigation

Results. The six-month study produced 42 C2 endpoints, 6 build clusters, 9 production YARA rules and 1 Sigma rule — validated against a 400k-sample public corpus at zero false positives. Three ISPs hosted on the C2 list were notified, and two endpoints were sinkholed within a month.

ID Finding Vector Category
F-01 Runtime key derivation defeats static config dump Config scheme Novel
F-02 Plaintext TLV C2 with leaking scan directives Protocol High
F-03 Modified UPX header breaks stock unpackers Packing High
F-04 6 build waves share one loader skeleton Lineage Intel

Recommendations

  1. Block the C2 list — the 42 endpoints and the kill-switch domain are production-ready; consume via the IOC feed, not a one-time blocklist.
  2. Alert on TLV fingerprints — the Sigma rule matches the beacon pattern byte-for-byte regardless of payload encryption.
  3. Watch for build wave G — the loader skeleton YARA will catch it; anything matching F-01 key derivation is same-family.
  4. Honeypot network expansion — the same telemetry setup feeds this study; more device profiles mean more variant coverage.

The full IOC feed and YARA package are shared on request — the study is deliberately kept reproducible so other analysts can extend it rather than take it on faith.
